本頁是本站的正式撰寫規範。所有手冊，文件與頁面都依此撰寫，`npm run lint:prose` 會自動檢查標點與空格規則。

## 語言與用詞

- 使用繁體中文與台灣慣用語，例如 "設定"，"伺服器"，"程式碼"，不使用 "配置"，"服務器"，"代碼"。
- 技術名詞保留英文，例如 runner，executor，job，pipeline，stage，artifact，cache，tag。第一次出現時可以在括號內補充中文說明。
- 一個概念只用一個詞，一個詞只表示一個概念。同一份手冊中不混用 "作業" 與 job。
- 產品與專有名詞依官方大小寫，例如 GitLab，GitLab Runner，Docker，Kubernetes，Podman。一般名詞用小寫，例如 runner，executor。
- 一句話只表達一個重點。說明步驟時使用祈使句，例如 "執行下列指令"。
- 不寫沒有資訊的句子，例如 "本節將介紹以下內容"。

## 標點符號

全形標點只保留逗號 `，` 與句號 `。`，其餘標點一律使用半形。

| 用途 | 使用 | 不使用 |
| --- | --- | --- |
| 逗號，句號 | `，` `。` | `,` `.` (接在中文後面時) |
| 括號 | `( )` `[ ]` | `（ ）` `【 】` |
| 冒號，分號 | `:` `;` | `：` `；` |
| 問號，驚嘆號 | `?` `!` | `？` `！` |
| 引號 | `"..."` | `「...」` `『...』` `“...”` |
| 列舉 | `，` | `、` |
| 破折號，刪節號 | 改寫句子 | `—` `–` `…` |

## 空格

- 中文與英文，數字之間加一個空格，例如 `使用 Docker 執行 3 個 job。`
- 中文與半形符號之間加一個空格，例如 `使用率 80% 時清理`。
- 括號與引號只在外側加空格，內側不加，例如 `使用 Docker executor (容器隔離) 執行 job。`
- 冒號，分號，問號與驚嘆號緊接前一個字，後面加一個空格，例如 `注意: 這一步需要 root。`
- 半形符號與全形 `，` `。` 之間不加空格，例如 `設定 "concurrent"，"limit" 兩個值。`
- 斜線 `/` 前後不加空格，例如 `shell/docker executor`。
- 數字與單位之間加空格，例如 `10 GB`，百分比除外，例如 `80%`。
- 標題，清單與表格儲存格同樣適用上述規則。

## Markdown 標記

Markdown 標記視為半形，外側與中文之間加空格，內側不加。

| 標記 | 正確 | 錯誤 |
| --- | --- | --- |
| 連結 | `請參考 [官方文件](https://docs.gitlab.com/) 的說明。` | `請參考[官方文件](https://docs.gitlab.com/)的說明。` |
| 粗體 | `這是 **重點** 文字。` | `這是**重點**文字。` |
| 行內程式碼 | ``設定 `concurrent` 為 4。`` | ``設定`concurrent`為 4。`` |

- 每個段落與每個清單項目寫在同一行原始碼內，不要手動換行。中文之間的換行在瀏覽器中會顯示成多餘的空格。
- 斜體在中文中不易閱讀，需要強調時使用粗體。

## 頁面類型

每份手冊的頁面分成四種類型，每一頁只屬於一種類型。

| 類型 | 目的 | 讀者的問題 | 目錄 |
| --- | --- | --- | --- |
| 概念 | 解釋原理與設計理由 | 這是什麼? 為什麼這樣設計? | `concepts/` |
| 操作指南 | 完成一個具體任務 | 我要怎麼做到某件事? | `guides/` |
| 參考 | 完整列出設定，指令與欄位 | 這個選項的確切意思是什麼? | `reference/` |
| 實作練習 | 帶讀者一步一步動手學習 | 我要怎麼從零開始練習? | `labs/` |

- 概念頁不放操作步驟，需要時連到操作指南。
- 操作指南從讀者的目標出發，列出先決條件，步驟與驗證方式。
- 參考頁以表格或清單呈現，內容與官方文件一致，並附上官方文件連結。
- 一個主題需要不同類型的內容時，拆成多頁並互相連結。

## 實作練習的結構

每個實作練習依序包含下列章節:

1. **目標**: 完成後讀者能做到什麼。
2. **先決條件**: 需要的帳號，工具與先完成的練習。
3. **步驟**: 使用 `<Steps>` 元件，每一步只做一件事。
4. **驗證**: 讀者如何確認結果正確，附上預期輸出。
5. **清理**: 移除練習建立的資源。
6. **延伸挑戰**: 不附答案的進階題目。

練習開頭註明核對過的版本與驗證方式。只依官方文件核對，沒有實際執行時，寫成 `依官方文件核對: GitLab Runner 18.5 (未實機執行)`。

## Frontmatter

每一頁都必須有 `title` 與 `description`。`description` 用一句話說明頁面內容，會出現在搜尋結果與連結預覽。

```yaml title="frontmatter 範例"
---
title: 安裝與註冊 runner
description: 在 Linux 主機與容器中安裝 GitLab Runner，並以 runner authentication token 註冊。
sidebar:
  label: 安裝與註冊
  order: 1
---
```

- `sidebar.label` 是側邊欄顯示的短標題，`title` 太長時才需要設定。
- `sidebar.order` 決定同一群組內的排序，數字小的在前。

## 連結

- 站內連結使用含 base 與結尾斜線的絕對路徑，例如 `/handbook/zh-tw/ci/gitlab-runner/`。建置時會檢查站內連結，相對路徑會被拒絕。
- 版本相關的事實，例如 token 流程，棄用功能，旗標名稱與預設值，連到 `docs.gitlab.com` 等官方文件。
- `localhost`，`127.0.0.1` 與私有主機的網址寫在行內程式碼或程式碼區塊中，不寫成連結。連結檢查會拒絕本機網址。

## 程式碼區塊

- 每個程式碼區塊都標註語言，例如 `sh`，`toml`，`yaml`。
- 代表檔案內容的區塊加上 `title`，例如 `title="config.toml"`。
- 指令前不加提示符號 `$`，讓讀者可以直接複製。指令本身包含 `$` 時保留，例如 `$HOME`。
- 指令輸出放在另一個程式碼區塊，語言標成 `text`。
- 程式碼區塊與行內程式碼中的內容不受本頁的標點規則限制。
- `<FileTree>` 中不使用 `...` 作為省略項目，每個目錄至少列出一個子項目。`...` 與空目錄都會被轉成刪節號。

## 提示框

使用 Starlight 的提示框標示需要特別注意的內容，不要用粗體段落代替。

| 語法 | 用途 |
| --- | --- |
| `:::note` | 補充說明 |
| `:::tip` | 建議作法或捷徑 |
| `:::caution` | 容易出錯或有副作用的操作 |
| `:::danger` | 可能造成資料遺失或安全風險的操作 |

:::caution[範例]
`privileged = true` 讓 job 容器取得主機的完整權限，只在信任的專案上使用。
:::

## 檢查

提交前執行下列指令，CI 也會執行相同的檢查:

```sh
npm test
npm run lint:prose
npm run build
```

`npm run lint:prose` 會列出違反標點與空格規則的檔案與行號。`npm run build` 會檢查站內連結。
